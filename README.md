# igo

![AI-Driven Development](https://img.shields.io/badge/AI%20Driven-Development-cccccc)

Generate `.gitignore` files from [github/gitignore](https://github.com/github/gitignore)
templates.

The common templates ship inside the binary, so `igo go macos vscode` works
with no network and no config. Anything else is fetched once and cached.

## Install

```bash
go install github.com/rstnk/igo/cmd/igo@latest
```

Or build from source:

```bash
make install
```

## Usage

List the templates you want, in the order you want them:

```bash
igo go macos vscode
```

That writes a `.gitignore` in the current directory combining all three.
Nothing is added for you: no OS or editor defaults, no environment
detection. What you type is what you get.

```bash
igo python --stdout          # print instead of writing
igo rust jetbrains -o api/.gitignore
igo go macos --force         # replace an existing .gitignore
igo list                     # see what is available
igo list jet                 # filter the list
igo update                   # refresh templates from GitHub
```

Names are case-insensitive, and common shorthands work: `vscode`, `golang`,
`py`, `osx`, `win`, `idea`, `pycharm`, `js`, `cpp`, `latex`.

When a name is ambiguous, give the full upstream path:

```bash
igo community/CFML/ColdBox
```

### Commands

| Command | Behavior |
|---|---|
| `igo <template>...` | Generate a `.gitignore` from the listed templates |
| `igo list [filter]` | List available templates and where each one comes from |
| `igo update` | Refresh the template list and cached templates from GitHub |

### Flags

| Flag | Behavior |
|---|---|
| `-o, --output <path>` | Output path (default `.gitignore`) |
| `--stdout` | Print to stdout instead of writing a file |
| `--force` | Overwrite an existing file without asking |
| `--offline` | Fail rather than fetch over the network |
| `--cache-dir <path>` | Override the cache location |

## Where templates come from

`igo` tries three sources in order, and stops at the first hit:

1. The snapshot compiled into the binary: Go, Python, R, macOS, Linux,
   Windows, VSCode, JetBrains, and Zed.
2. The local cache, holding anything fetched on an earlier run.
3. `raw.githubusercontent.com`, which is then cached.

`igo list` marks each template `embedded`, `cached`, or `fetch` so you can
tell which ones need a connection.

The list of what exists upstream is also compiled in, so `igo list` and
typo suggestions work offline too. `igo update` refreshes that list and
re-downloads every cached template, keeping a machine offline-ready with
current content.

## Overwriting

`igo` will not silently replace a `.gitignore` it did not just write:

- Identical content is a no-op, so re-running is always safe.
- Different content prompts on a terminal, and fails elsewhere. Pass
  `--force` to skip the question.

## How templates are combined

Blocks appear in the order you listed them, each under a header naming its
source:

```
# Generated by igo
# Templates: Go, macOS

# --- Go ---
# Binaries for programs and plugins
*.exe
...

# --- macOS ---
.DS_Store
...
```

A pattern that already appeared in an earlier block is dropped. When that
empties out a group of patterns, its comments go too, so the file never
explains rules that aren't there. Blank-line structure inside each template
is preserved.

## Cache

Fetched templates live in `$XDG_CACHE_HOME/igo` when that variable is set,
and in the platform cache directory otherwise (`~/Library/Caches/igo` on
macOS, `~/.cache/igo` on Linux). Each template is stored under its upstream
path with a sidecar `.json` recording the source URL and fetch time.

Cached templates are reused until you run `igo update`.

## Development

```bash
make help      # list targets
make test      # go test ./...
make lint      # go vet, plus staticcheck when installed
make build     # bin/igo
make vendor    # re-snapshot embedded templates from github/gitignore
```

`make vendor` runs `go generate ./templates`, which rewrites
`templates/data/` from upstream: the embedded templates, `index.txt`
listing everything upstream publishes, and `embedded.txt` recording which
paths the snapshot covers. Run it when refreshing the built-in templates
for a release; it is the only step that needs a network connection.

### Changing which templates are embedded

Edit the `core` list in `tools/vendor-templates/main.go` and re-vendor:

```go
var core = []string{
	"Go",
	"Python",
	// ...
	"Rust", // added
}
```

```bash
make vendor
```

Entries are exact upstream paths, case-sensitive, without the `.gitignore`
suffix. Find the one you want with `igo list --names | grep -i rust`.

Two rules the generator and tests enforce:

- A path that no longer exists upstream fails `make vendor` rather than
  shipping a stale snapshot.
- Base names must stay unique, since the snapshot stores files flat.
  Embedding both `Racket` and `community/Racket` fails the tests.

If you remove a template, update the source list above, and the `want`
lists in `templates/embed_test.go` and `internal/cli/cli_test.go` that pin
the expected core set.
